# Подготовка TIBON к публикации

## Шлюз NGINX и HTTPS

Шаблон [nginx.conf.example](nginx.conf.example) рассчитан на один NGINX перед SSR и несколькими процессами API. Подставьте домен и пути к сертификату, настройте продление сертификата и проверьте шаблон через nginx -t. Оставьте порты приложений на loopback. В изолированной контейнерной сети укажите реальные адреса upstream и ограничьте сетевой доступ к API адресом шлюза.

- Шлюз направляет публичный liveness, POST заявок и GET меню в FastAPI. Документация и диагностика БД через шлюз возвращают 404. SSR обслуживает остальные страницы.
- Общая память NGINX связывает лимиты между worker-процессами шлюза, независимо от числа процессов FastAPI. Начальные лимиты составляют 8 заявок и 8 скачиваний меню в минуту на адрес, с отдельной квотой 60 заявок в минуту на сайт. Шаблон разрешает короткие всплески. При превышении возвращается 429 с Retry-After. Лимиты FastAPI остаются раздельными и действуют на каждый процесс. При нескольких экземплярах шлюза для общего лимита потребуется уровень, который разделяют все экземпляры. [Документация NGINX](https://nginx.org/en/docs/http/ngx_http_limit_req_module.html)
- NGINX заменяет входящие X-Forwarded-For, X-Forwarded-Proto и X-Forwarded-Host. Укажите в TRUSTED_PROXY_IPS только непосредственный IP NGINX. При запуске Uvicorn передайте --no-proxy-headers, чтобы обработку заголовков выполняла только настроенная middleware FastAPI. Если перед NGINX появится CDN или балансировщик, настройте точное доверие к этому узлу и проверку клиентского IP до включения такой схемы. [Документация Uvicorn](https://uvicorn.dev/settings/#http)
- В production задайте API_DOCS_ENABLED=false. DATABASE_HEALTH_ENABLED=false отключает проверку БД полностью. Если мониторингу нужна проверка, оставьте её включённой и опрашивайте закрытый порт API. Публичная проверка /api/v1/health работает в обоих режимах.
- Шаблон включает HTTPS и базовые заголовки, в том числе HSTS с начальным max-age 300. Проверьте перенаправление, HTTPS, заголовки ошибок и ответы PDF до увеличения max-age. CSP добавляйте как Report-Only на стенде. Затем проверьте nonce для inline-скриптов React Router, гидратацию, стили, шрифты, формы и внешнюю карту после принятия cookie. Включайте обязательную CSP после устранения неожиданных нарушений.

Пример команды для API на хосте шлюза:

    python -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 2 --no-proxy-headers

## Роли PostgreSQL

1. [postgresql-roles.sql](postgresql-roles.sql) создаёт отдельную БД tibon и роли для нового развёртывания. Выполните его под доверенной ролью подготовки кластера на изолированном стенде. Для существующей БД сначала спланируйте перенос владения и прав.
2. Настройте пароли ролей через секрет-хранилище или интерактивную команду psql \password. Для Alembic используйте POSTGRES_USER=tibon_migrator и пароль мигратора. Выполните alembic upgrade head из backend. Роль мигратора владеет прикладной схемой.
3. [postgresql-grants.sql](postgresql-grants.sql) выдаёт минимальные права для текущих операций API и Telegram worker. Выполните его в БД tibon от tibon_migrator после миграций. API и worker запускайте с POSTGRES_USER=tibon_app и собственным паролем. При новых таблицах пересмотрите явный список прав.
4. Для удалённой БД установите POSTGRES_SSLMODE=verify-full, предоставьте клиенту доверенный CA и используйте имя хоста из сертификата. Ограничьте доступ к БД сетью приложения и миграций. Проверьте резервное копирование, восстановление и права на приватные PDF. [Документация PostgreSQL](https://www.postgresql.org/docs/18/ddl-priv.html)

## Сборка и совместимость

- Перед установкой Python-зависимостей задайте в сборочной .venv проверенную версию инструмента. Для текущего набора advisory проверена pip 26.3. Команда меняет только pip. [Релиз на PyPI](https://pypi.org/project/pip/26.3/)

      python -m pip install --no-deps --only-binary=:all: pip==26.3

- Порядок выкладки для согласия — миграция 0005, затем backend, затем frontend. lead-consent-v1 обозначает текущий комплект текстов заявок, обратного звонка и меню. Поля format и source определяют форму. При утверждённом изменении текста добавьте поддерживаемую версию в схему API, затем обновите идентификатор в клиенте и сохраните утверждённый текст этой версии. Старые клиенты могут опустить consent_version. У них версия сохраняется как NULL. У записей до миграции consent_version и consented_at остаются NULL. Для новых записей сервер фиксирует время приёма согласия.
- До открытия форм согласуйте обработку данных и уведомления по TIBON-01. На стенде проверьте все три формы, оба PDF, ответы 429, закрытие внутренней диагностики на шлюзе и текущий SSR с гидратацией.
