# PAGE SPECIFICATION — новый сайт TIBON

Спецификация страниц для реализации. Анализ референса, недостатки и обоснование структуры — в `docs/REFERENCE_AUDIT.md` (далее — **Audit**), здесь не повторяются. Ссылки вида «Audit §9» указывают на разделы аудита.

Все факты, цены, контакты и часы в текстах — **плейсхолдеры `[уточнить]`**, значения приходят из CMS. Никаких выдуманных цифр в коде и контенте.

## 0. Общие правила

- Стек и структура — по `docs/ARCHITECTURE.md`; контент страниц не хардкодится, а приходит из API.
- Mobile-first; публичные страницы рендерятся на сервере (React Router framework mode, SSR) для индексации и свежего CMS-контента — см. `ARCHITECTURE.md` §SEO & rendering.
- Тексты-плейсхолдеры в макетах помечаются `[уточнить]` и не попадают в прод.
- Пустая сущность (нет блюд, нет фото, нет услуг) → осмысленное пустое состояние, а не пустой блок.

## 1. Дизайн-токены и сетка

### 1.1 Цвета

| Токен | Значение | Роль |
| --- | --- | --- |
| `--color-milk` | `#F7F4EE` | Фон страницы |
| `--color-sand` | `#E7DED0` | Поверхности, разделители, фон карточек-заглушек |
| `--color-dark` | `#25251F` | Основной текст, футер, тёмные секции |
| `--color-terracotta` | `#B66C50` | Primary-кнопки, акцентные линии, крупные акцентные заголовки |
| `--color-terracotta-ink` | `#8F4E37` | Текст-ссылки и мелкий акцентный текст на светлом (контраст ≥ 4.5:1) |
| `--color-olive` | `#737B61` | Теги, чипы, вторичные акценты, иконки |
| `--color-olive-ink` | `#5E6550` | Мелкий текст на оливковых/светлых подложках (контраст ≥ 4.5:1) |

Правила контраста: терракота `#B66C50` и олива `#737B61` на молоке дают ~3.7–4.1:1 — допустимы только для крупного текста (≥ 24 px regular / ≥ 18.66 px bold) и UI-элементов; для body и мелких ссылок использовать `*-ink`-варианты. Белый текст на терракоте (≈ 4.0:1) — только крупный, либо тёмный текст `--color-dark` на светлой подложке.

### 1.3 Сетка, отступы, форма

- Контейнер: max 1280 px; поля 16 / 24 / 40 px (мобайл / планшет / десктоп); 12 колонок, gutter 24 px.
- Вертикальный ритм: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128 px. Секция: 64 px (мобайл) / 96–128 px (десктоп).
- Радиусы: 2 px (карточки, изображения, кнопки), 999 px — только мобильный sticky-CTA и чипы.
- Границы: 1 px `--color-sand`; тени не используются (допустима одна мягкая тень у sticky-панели и лайтбокса).
- Движение: 150–300 мс, easing `cubic-bezier(.2,.6,.2,1)`; `prefers-reduced-motion` отключает.

### 1.5 Доступность (обязательно на всех страницах)

Skip-link; один H1 на страницу; порядок заголовков без пропусков; `:focus-visible` — 2 px `--color-terracotta-ink`, offset 2 px; контраст текста ≥ 4.5:1; alt для всех содержательных изображений (`alt=""` только для декоративных); тач-таргеты ≥ 44 px; ошибки формы связаны через `aria-describedby`; лайтбокс и меню — фокус-трап; никакой информации только цветом.

## 2. Формы и заявки (единая спецификация)

### 2.1 Типы заявок

`callback` (обратный звонок), `event` (праздник/МК), `kids` (детский праздник), `rental` (аренда), `service` (доп. услуга), `menu` (подбор меню). Тип определяет набор полей и предзаполнение.

### 2.2 Поля

| Поле | Тип | Обяз. | Валидация | Примечание |
| --- | --- | --- | --- | --- |
| `name` | text | да | 2–60 символов, trim, без цифр | `autocomplete="name"` |
| `phone` | tel | да | маска `+7 (___) ___-__-__`, ровно 10 цифр после +7 | `inputmode="tel"`, `autocomplete="tel"` |
| `email` | email | нет | RFC-подобная проверка, ≤ 254 | `autocomplete="email"` |
| `type` | hidden/select | да | из списка §2.1 | Задаётся точкой входа |
| `format_id` | select | для `event`/`kids` | активный формат из CMS | Предзаполняется со страницы |
| `service_id` | select | для `service` | активная услуга из CMS | Предзаполняется из карточки |
| `date` | date | для `event`/`kids`/`rental` | не в прошлом, ≤ +12 мес | `min` = сегодня |
| `time_start` | time | нет | шаг 30 мин | Для аренды |
| `hours` | number | для `rental` | 1–12, целое | Минимум из настроек тарифа |
| `guests` | number | для `event`/`kids`/`rental` | 1–50, целое | Подсказка «минимум [уточнить]» |
| `child_age` | number | для `kids` | 1–17 | — |
| `comment` | textarea | нет | ≤ 1000, счётчик | Аллергии, пожелания |
| `consent` | checkbox | **да** | должен быть отмечен | Ссылка на политику, `target="_blank"` |
| `honeypot` | hidden | — | должен быть пуст | Антиспам |
| `source` | hidden | — | `page_url`, `utm_*` | Аналитика |

### 2.3 Поведение

- Валидация: на blur после первой попытки отправки и на submit; ошибка — под полем, текст конкретный («Укажите номер телефона полностью»); фокус переводится на первое ошибочное поле; сводка ошибок для скринридеров.
- Состояния: `idle` → `submitting` (кнопка disabled, `aria-busy`, текст «Отправляем…») → `success` (форма заменяется блоком успеха, фокус на заголовок) | `error` (toast + inline, кнопка снова активна). Двойная отправка исключена.
- Кнопка: «Отправить заявку». Подпись под кнопкой: «Отправляя заявку, вы соглашаетесь с политикой обработки персональных данных. Заявка не является подтверждением бронирования.»
- Экран успеха: «Заявка отправлена. Мы свяжемся с вами в рабочее время ([часы уточнить]), чтобы согласовать дату и детали. Бронирование подтверждает менеджер.» + телефон и ссылка «Отправить ещё одну заявку».
- Ошибка сети: «Не удалось отправить заявку. Проверьте соединение или позвоните: [телефон].»
- Лимит: 429 → «Слишком много попыток. Попробуйте позже или позвоните: [телефон].»

### 2.4 Модель статусов (не UI-подтверждение)

`new → contacted → confirmed | declined → archived`. Создание заявки **не** резервирует дату и не меняет доступность слотов. `confirmed` выставляет только администратор. Клиентские тексты никогда не используют «вы забронировали» до подтверждения менеджером. Уведомление админу — сразу при создании (`new`), клиенту — только после смены статуса на `confirmed`/`declined` (шаблоны согласовать, Audit §10 п. 14).

### 2.5 Точки входа

Модальное окно/панель (desktop — справа, mobile — sheet) с короткой формой (имя, телефон, согласие) + страница `/zayavka/` с полной формой для deep-link. Все CTA на сайте ведут в одну из этих точек с предзаполненным `type`.

## 3. Страницы

### 3.1 Главная — `/`

**Назначение:** за 5 секунд объяснить, что это кулинарная студия, показать форматы и увести в заявку. Закрывает провал Audit §8 п. 1.

**Секции по порядку:**

1. **Hero.** Слева: eyebrow «Кулинарная студия · [город]», H1 «Готовить вместе — это событие», lead 1–2 строки о форматах, 2 CTA — primary «Оставить заявку», secondary «Смотреть форматы» (якорь на блок 2). Под CTA — 3 чипа фактов: «от [N] гостей», «[N] часа», «взрослым и детям». Справа: фото 4:5 (процесс приготовления, естественный свет), подпись-капшн.
2. **Форматы.** H2 «Выберите формат», 4 карточки: «Для взрослых», «Для детей», «Аренда студии», «Дополнительные услуги». Асимметричная сетка: 2 карточки крупные (7/5 колонок), 2 — узкие. У каждой: фото, 1 строка описания, ссылка-стрелка.
3. **Как это проходит.** H2 + 4 шага: «Заявка» → «Согласование даты и меню» → «Мероприятие» → «Впечатления». Тексты нейтральные, без обещаний сроков.
4. **Меню-тизер.** Две колонки: фото блюда 3:2 + текст (H2 «Меню», 2 строки, 3 тега кухонь `[уточнить]`), ссылка «Смотреть меню».
5. **Доп. услуги.** H2 + горизонтальная лента 3–5 `ServiceCard` + ссылка «Все услуги».
6. **Галерея-превью.** Mosaic 5–7 фото (только реальные фото студии), ссылка «Вся галерея».
7. **CTA-полоса.** Тёмный фон: H2 «Обсудим ваш праздник», 1 строка, короткая форма (имя, телефон, согласие) или кнопка «Оставить заявку» — выбрать одно, не дублировать.
8. **Footer.**

**CTA:** «Оставить заявку» (primary, hero + header), «Смотреть форматы», «Смотреть меню», «Все услуги», «Вся галерея».
**Данные:** `SiteSettings` (город, телефон), `Format` (4 записи: slug, title, cover, short_desc), `Step` (4), `MenuTeaser` (фото, текст, теги), `Service` (3–5 featured), `MediaItem` (5–7 featured), SEO-поля страницы.
**Адаптив:** hero 7/5 → одна колонка (текст, затем фото 3:2); карточки 4 → 2 → 1; лента услуг — горизонтальный скролл со snap на мобайле; sticky-панель действий.

### 3.5 Аренда студии — `/arenda/`

**Назначение:** дать организатору/фотографу достаточно фактов, чтобы проверить пригодность пространства, и собрать заявку с датой и часами. На референсе нет ни характеристик, ни заявки (Audit §3.4).

**Секции:**

## 6. Сквозные требования к реализации

- **SEO:** уникальные `title`/`description` из CMS, OG-теги, canonical, `BreadcrumbList` на внутренних, `Organization`/`LocalBusiness` в layout, `Service`/`Offer` на форматных страницах и услугах. Один H1. Хлебные крошки видимы.
  *Рендеринг:* публичные страницы отдаются SSR (React Router framework mode), поэтому мета-теги и контент попадают в HTML без отдельного prerender-шага. Решение и альтернативы — `ARCHITECTURE.md` §SEO & rendering.
- **Производительность:** LCP-изображение hero — `fetchpriority="high"`, без lazy; остальные lazy; цель LCP < 2.5 s на 4G, CLS < 0.1 (фиксированные `aspect-ratio`).
- **Аналитика:** события `lead_form_open`, `lead_submit`, `lead_success`, `lead_error`, `cta_click` с параметрами `type`, `page`, `format`, `service`.
- **Контент:** ни одного выдуманного факта; всё, чего нет в CMS, скрывается, а не заполняется заглушкой на проде.
- **Проверка:** сквозной E2E — «главная → формат → заявка → успех» и «меню → PDF», плюс проверка, что заявка не меняет статус без администратора.
