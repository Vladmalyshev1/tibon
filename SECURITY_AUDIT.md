## Модель угроз и охват

- **Границы доверия.** Браузер обращается к SSR и API, FastAPI доверяет PostgreSQL и приватному файловому каталогу. Worker читает outbox и контактные поля и отправляет уведомления в настроенный Telegram-чат. После отдельного согласия браузер загружает iframe карты. Защищаемые данные — контакты, комментарий, ключ PDF, bot token, пароль БД и резервные копии.
- **SSR, ввод и XSS.** В коде до операций HTML не найден путь пользовательского ввода через dangerouslySetInnerHTML, innerHTML или eval. Loader меню выбирает тип из конечного набора. Публичный origin берётся из серверной переменной с проверкой протокола. Внутренний API URL применяется для dev-прокси. Cookie consent хранит только выбор. Клиент отправляет форму на относительный URL с credentials: omit и redirect: error. ## Находки и исправления

### TIBON-01 · High · Обработка персональных данных не готова к запуску

Приложение сохраняет имя, телефон и дополнительные поля в PostgreSQL. При включённом worker эти данные попадают в Telegram. В политике открыты вопросы об операторе, получателях уведомлений, сроках хранения, удалении и канале обращений. protect_content ограничивает пересылку средствами платформы, а состав участников и срок хранения определяются отдельно. Доказательства — backend/app/models/lead.py:64–107, backend/app/services/telegram.py:27–49, 122–132, frontend/app/routes/privacy.tsx:42, 61–91, 105–115.

**До запуска форм** согласовать политику и текст согласия, определить доступ и процедуру удаления в БД, резервных копиях и чате. Подтвердить закрытый список получателей. Свести Telegram-уведомление к минимально необходимым полям или передавать ссылку в защищённый рабочий интерфейс.

### TIBON-02 · Medium · Ограничение спама действует на один процесс

Каждый процесс API хранит отдельный счётчик. Лимит — восемь запросов в минуту на группу адресов. POST и скачивание делят лимит. Каждая новая принятая заявка ставит задачу в outbox. Идемпотентность ограничивает повторы одной операции, а общий предел при нескольких процессах и защита от распределённого спама в коде отсутствуют. Возможны лишние записи, рост очереди и задержка уведомлений. Доказательства — backend/app/main.py:22–26, backend/app/services/rate_limit.py:7–49, backend/app/api/leads.py:32–52, 176–183, backend/app/services/leads.py:43–61.

**До запуска форм** ввести общие лимиты на шлюзе или в общем хранилище, разделить квоты записи и выдачи меню, наблюдать за очередью. Ограничить список доверенных прокси и проверить, что шлюз задаёт канонические заголовки пересылки.

### TIBON-03 · Medium · Локальный production SSR отвечает без защитных заголовков

На четырёх HTML-ответах отсутствовали CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy и Permissions-Policy. SSR устанавливает Content-Type, React Router добавляет inline-скрипты. Промежуточный шлюз может добавлять заголовки. HSTS оценивается на будущем HTTPS-ресурсе. Доказательства — frontend/app/entry.server.tsx:17–28, frontend/app/root.tsx:18–22, passive-browser.json и пассивные правила ZAP 10020, 10021 и 10038.

**До публикации** проверить HTTPS и перенаправление, HSTS на HTTPS, nosniff, политику referrer и frame-ancestors. CSP вести от Report-Only к применению после проверки nonce, гидратации, шрифтов и разрешённого iframe карты.

### TIBON-04 · Medium · Привилегии и режим TLS PostgreSQL требуют production-конфигурации

В официальном образе PostgreSQL переменная POSTGRES_USER создаёт начальную привилегированную роль. По умолчанию приложение использует то же имя. При переносе этой схемы в production runtime может получить лишние полномочия. sslmode=prefer не гарантирует TLS и проверку имени сервера. Compose привязывает локальную БД к loopback. Фактические production-роли и TLS не установлены. Доказательства — infra/compose.yaml:2–11, backend/app/config.py:23–31, 50–59, backend/app/database.py:6–12. [Документация образа PostgreSQL](https://hub.docker.com/_/postgres)

**До публикации** разделить роли bootstrap, миграций и сервиса. Ограничить доступ к сети БД, включить проверку сертификата для удалённого PostgreSQL и защитить резервные копии.

### TIBON-05 · Medium · Устаревший pip в окружении сборки

pip-audit подтвердил семь уникальных записей для pip 23.2.1 — CVE-2023-5752, CVE-2025-8869, CVE-2026-1703, CVE-2026-3219, CVE-2026-6357, CVE-2026-8643 и CVE-2026-13346. Доказательство — pip-audit.json и список установленных пакетов. pip отсутствует среди runtime-зависимостей (backend/pyproject.toml:9–19). Риск относится к установке пакетов. Нижняя граница версии, закрывающей все семь перечисленных advisory, — 26.2. [Журнал изменений pip](https://pip.pypa.io/en/stable/news/)

**До новой production-сборки** использовать проверенную актуальную версию pip в сборочном окружении. Зафиксировать набор зависимостей и повторить аудит по фактическому образу.

### TIBON-06 · Low · OpenAPI и диагностика доступны на порту приложения

На локальном FastAPI /openapi.json, /docs и /redoc возвращают 200. Endpoint /api/v1/health/db инициирует запрос к базе и сообщает её доступность без деталей. Фактическая видимость снаружи зависит от шлюза. Доказательства — backend/app/main.py:32–47, backend/app/api/health.py:25–33, zap-passive-final.json.

**Исправление.** Ограничить документацию и проверку БД внутренней сетью или правилами шлюза, сохранив простой liveness.

### TIBON-07 · Low · Отметка согласия не привязана к версии текста

База хранит согласие и время заявки. После обновления текста по записи нельзя определить, какую версию видел пользователь. Доказательства — backend/app/schemas/lead.py:22–36, 67–72, backend/app/models/lead.py:91–107.

**Исправление.** Определить, какое доказательство согласия нужно процессу, и хранить идентификатор согласованной версии вместе с записью.

### TIBON-08 · Low · API допускает противоречивую классификацию заявки на PDF

Интерфейс задаёт согласованные format и source, а backend принимает их независимо для форматов, отличных от callback. Файл выбирается по source. Можно сохранить неверную классификацию заявки и уведомления. Проверки UUID, ключа и согласия сохраняются. Доказательства — frontend/app/components/pages/MenuDownloadForm.tsx:28–35, backend/app/schemas/lead.py:29–36, 60–65, backend/app/models/lead.py:49–59, backend/app/api/leads.py:189–195.

**Исправление.** Зафиксировать допустимые пары и проверять их на сервере. Пара UUID и ключа даёт временное предъявительское разрешение. Если бизнес требует доказательства владения номером, эту гарантию следует определить отдельно.

## Триаж и границы проверки

- Пассивное предупреждение ZAP 10202 о CSRF не подтверждает уязвимость анонимной формы без сессии. Сохранять проверки JSON и CORS. Спам покрывает TIBON-02.
- Пассивное 10031 о потенциальном контроле HTML-атрибута — сигнал для проверки. По исходникам loader меню выбирает только фиксированные типы. Путь к выполнению HTML или JavaScript не найден. Информационные правила 10027 и 10109 сами по себе уязвимость не устанавливают.
- Сообщения о внешнем JS и SRI (10017 и 90003) относятся к автоматически сгенерированным страницам документации FastAPI. Они не показывают загрузку этого кода на публичных SSR-страницах. Мера для production — ограничение из TIBON-06. Внешние ресурсы документации не загружались.
- Синтаксис sqlalchemy.text сам по себе не означает SQL injection. Строки в проверенных репозиториях константны. Встроенный Python TimeoutError наследует OSError. Проверенные обработчики OSError покрывают таймауты операций БД.
- Cookie приложения для проверки HttpOnly, Secure и SameSite не наблюдались. Хранилище внешней карты осталось за пределами аудита. Отсутствие совпадений Semgrep и Gitleaks ограничено правилами и охватом.
- Не проверены рабочий PostgreSQL и доставка, production HTTPS, реальные права хранения PDF, внешние журналы и ранее выданные токены. Полная проверка отправки формы и выдачи PDF остаётся для изолированного стенда с тестовой БД и заглушкой Telegram.
